# 路线图

按**风险从高到低**排，不按"容易先做"排。
每个里程碑都有可判定的验收标准——"感觉还行"不算通过。

原则：**前一个里程碑不过，不开下一个。** 尤其是 M1 和 M2，
它们是"这游戏到底好不好玩"的答案，不过就该改方向而不是继续堆功能。

## 现状速览（2026-08-25）

- **M0 战斗骨架**：完成。
- **M1 战斗深度**：核心机制早已完成；这一轮又新增了完美取消、首领连续技，

  冲刺残影/落地环/走动起伏等纯程序化视觉效果。**但 M1 自己定的 4 条量化

## M1 · 战斗深度 —— 最高风险 ✅ 真机验收通过

目标：验证"这个战斗值不值得玩下去"。**不过就停，别往下做。**

### 要做

- [x] 五种敌人：杂兵 / 盾兵 / 远程 / 冲锋 / 精英
- [x] 处决机制（敌人 <25% 血可处决，回血回能）
- [x] 能量与技能（1 个范围技能起步）
- [x] 冲刺无敌帧 + 冷却
- [x] 敌人预警帧（冲锋和精英的起手要看得见）
- [x] 局内统计埋点（否则下面四条验收标准无从判定）
- [x] 完美取消（可取消窗口最早几帧接招获得伤害加成，奖励反应速度而不是
      纯粹背连招表，见 `GAME_DESIGN.md` 3.4.1）
- [x] 首领招式衔接连续技（阶段二范围技收招后强制接重击，避免孤立的
      一次性判定，见 `GAME_DESIGN.md` 3.5）
- [x] 响应真人定性反馈的一批手感修复：输入缓冲、收招段可自由走位、
      普攻二段收招死循环、受击硬直隐形延长、技能/处决腾空贴地、
      挥砍弧光/冲刺残影/落地环/走动起伏等纯程序化视觉效果

### 验收标准

1. **打法多样性**：录三局的按键序列，普攻占比 **< 60%**。
   如果还是一路平 A，说明深度不够，机制没生效。
2. **纵深有用**：盾兵和远程必须逼出纵深走位。
   统计：单局纵深移动距离 / 横向移动距离 **> 0.25**。
3. **处决被使用**：单局处决次数 **≥ 3**。用不上说明触发条件或收益不对。
4. **不觉得不公平**：所有致死伤害都有可见预警。逐个 review，不能有"凭空掉血"。

### 当前状态：机制实测通过，项目负责人已真机确认可继续

**必须分清两件事**：机制跑不跑得通，和这个战斗好不好玩。
下面的数字来自脚本 bot（`__game` 挂钩驱动，五局），只能证明**机制不是摆设**——
连脚本都打不出多样性的话，真人更不可能。**它不构成验收通过。**

| 标准 | 要求 | 脚本五局 | 机制判定 |
| --- | --- | --- | --- |
| 1 普攻占比 | < 60% | 31% / 39% / 33% / 46% / 47% | 5/5 达标 |
| 2 纵深比 | > 0.25 | 0.78 ~ 1.68，均值 1.12 | 5/5 达标 |
| 3 处决次数 | ≥ 3 | 0 / 4 / 3 / 3 / 3 | 4/5 达标 |
| 4 无预警致死 | 0 | 全部 0（含站桩挨打致死一局，14 次受击全部预警） | 通过 |

**验收第 1、2、3 条最终要以真人操作为准。**
玩完直接在控制台读 `__game.stats()`，四条标准的数字都在里面
（跨房间的整局汇总用 `__game.overallStats()`）。

上面这张表是完美取消、首领连续技、输入缓冲等一批新机制加进来**之前**
跑的，数字会有点过时——但表格的作用只是证明"机制不是摆设"，这个结论
不受后续加的这些东西影响。**真正卡住的是这张表从头到尾都没换成真人
数据**：这一轮虽然收到了大量真人的定性反馈（"丝滑不丝滑""连不连贯"）
并且逐条修了，但那是手感层面的问题排查，不等于第 1/2/3 条要的量化
按键序列。

### 后续持续观测

M2 开发和后续调平衡期间继续读取 `__game.overallStats()`，积累
`basicAttackRatio`、`depthRatio`、`executes`、`unwarnedLethal`。真机通过
解除了开工门槛，但不代表后续职业改动可以不做同一套回归。

调参过程中被实测推翻的两处设计（`[已验证]`）：

- **冲锋的突进距离必须大于它的起手距离**。第一版突进只有 62px，
  而它在 190px 外起手——蓄力、预警、突进整套演完，人还在两个身位外。
  这个敌人类型当时等于不存在。现在突进约 197px，且会冲过头。
- **冲刺必须能朝纵深方向**。冲刺原本写死沿朝向走，于是"用冲刺躲"
  永远是横向位移，而远程和冲锋的攻击本来就是水平直线，横着躲不开。
  改成按输入锁定方向后，纵深比从 0.218 直接跳到 0.98——
  第 2 条能不能过，卡的根本不是敌人设计，是冲刺少了一个维度。

### 判定

三条以上不达标 → 战斗深度不足，回头改机制，不是加内容。

## M2 · 职业差异 —— 次高风险 🚧 已开工

目标：验证职业是不是三种游戏，而不是三个数字。M1/M3 已获真机放行，
当前从不改变玩法的动作解析架构开始，再逐个实装职业。

### 需要先决策：解锁依赖冲突

`GAME_DESIGN.md` 6.1 写的是"职业由演武场（M5 的建筑）解锁"，但 M5 排在
M2 后面——按现在的顺序，职业系统做出来的时候，解锁它的建筑还不存在。

**决策**：M2 验证阶段三个职业默认全部可选，不经过任何解锁门槛；
等 M5 真正把经营层做出来后，再把"演武场解锁职业"这层套回去——数据结构
不需要为此改动，无非是选择界面要不要显示"未解锁"状态，是纯 UI 层面的
收口。这样能先验证"职业本身是不是三种游戏"这个风险最大的问题，
不用被"经营层还没做"卡住。

### 需要先决策：动作表怎么按职业分层查表

`ACTIONS: Record<ActionState, ActionDef>` 现在是全局唯一一张表，不只装
玩家招式——`idle`/`move`/`hit` 是玩家和敌人共用的，`aim`/`shoot`/`heavy`/
`bossSlam` 等一大串是敌人专属的，敌人没有"职业"这个概念。查过代码，
`ACTIONS[e.action]` 直接取值的调用点有 16 处，`canInterrupt`/
`isPerfectCancel`/`isActionInvulnerable`/`isActionAirborne` 这四个封装
函数的调用点还有 9 处——全部 25 处都已经拿到了完整的 `Entity`，往每处
多传一个职业参数是可行的，但表结构不能是"每个职业各开一张完整表"，
不然敌人专属动作、三份重复的 `idle`/`move`/`hit` 都没地方讲道理。

**决策**：新增 `PROFESSION_ACTIONS: Record<Profession, Partial<Record<ActionState, ActionDef>>>`，
只装三个职业各自**覆盖**的那几招（`slash`/`slash2`/`dash`/`skill`/
`execute`/`jump`/`airSlash`），`ACTIONS` 本身一个字不用改。开一个
`resolveAction(action, profession)`：`PROFESSION_ACTIONS[profession]?.[action] ?? ACTIONS[action]`，
25 处调用点全部改成走这一个函数。选这条路径还有个好处：M4"武器改变
招式组"是同一种"覆盖优先、退回上一层"的需求，只需要再叠一层——
`WEAPON_ACTIONS[weapon]?.[action] ?? PROFESSION_ACTIONS[profession]?.[action] ?? ACTIONS[action]`，
不用另起一套结构。这条现在只钉文档，不动代码。

### 要做

- [x] 三职业的动作数据集：重击 / 疾锋 / 术法各自的招式帧数、判定框、
      位移曲线，写进 `PROFESSION_ACTIONS`（见上面的分层查表决策）。
      复用 `core/actions.ts` 现成的 `ActionDef` 结构——这次为完美取消
      调过的字段（`cancelFrom`、`perfectCancelWindow`）和精英/首领已经
      在用的 `superArmor`，三个职业各自都用得上，不需要发明新概念。
      具体的攻防两端设计方向见 `GAME_DESIGN.md` 四、职业系统
- [x] `PlayerProfile` 增加职业字段，`resolveAction(action, profession)`
      取代散落各处的 `ACTIONS[e.action]`——现在这层映射（`attackAction`
      之类）只有敌人侧的 `ENEMY_PROFILES` 有，玩家侧目前是写死的一套，
      需要补上同等地位的职业层
- [x] 完美取消的取消窗口要按职业重新过一遍：疾锋三段各有窄窗口；术法

### 验收标准

1. **打法真的不同**：同一关用三个职业各打三局，
   三者的按键分布、平均交战距离、单局位移距离必须显著不同。
   数值接近 = 设计失败。真人验收之前，先用脚本自检一条辅助指标：
   三个职业的伤害/时间曲线形状应该明显不同（重击低频高伤、疾锋高频
   低伤、术法中频中伤带范围），这条能从 `ActionDef` 的帧数和伤害值
   直接算出来，不用等真人，能先拦住一次明显的设计失败
2. **不能有明显最优解**：三职业通关同一关的成功率差 **< 20%**。
3. **手感可辨识**：蒙住 UI 只看动作，能认出是哪个职业。

## M3 · 关卡与推进 ✅ 真机验收通过

原定「一关 4 波」的波次系统，改成 **DNF 式房间推进**——详细设计见
[docs/LEVEL_DESIGN.md](LEVEL_DESIGN.md)。改动理由：波次只有一个计数，
玩家不知道离终点多远；房间推进有小地图，且每间房尺寸、编成都能不同，
不会越打越腻。

- [x] 房间图与切换（清空开门、推镜过渡、玩家状态跨房间保留）
- [x] DNF 式小地图（手写网格坐标，首领房一进关即可见）
- [x] 六关编排，每关引入一种新敌人且第一次出场时单独出现，
      场地尺寸按敌人机制分配（例如冲锋教学间用 wide，它要助跑距离）
- [x] 局内三选一成长（锋芒 / 玄术 / 守元），独立奖励房夹在最后一场战斗和首领之间
- [x] 首领：分阶段，血量降到 50% 切阶段二，解锁范围技并召唤两个杂兵，
      六关终点房都是真首领（不再是精英群占位）
- [x] 结算界面

实测中发现并修复的机制缺陷 `[已验证]`：

- **终点首领清空就应结算，支线不能反过来成为强制主线**。此前
  `stageCleared` 要求地图所有房间都清空，玩家即使已击败终点首领，只要漏了
  一间支路仍不会结算，必须原路回去补图；这与地图里的“支线”以及“终点房”
  定义矛盾。现在改为首领房清空即通关，支线保留为主动承担风险换额外掉落。

- **门锁必须用固定帧数豁免，不能靠"走出判定圈才解锁"**。
  出生点离纵深门只有 37px，判定半径却是 46px，进门瞬间会被判定成
  「又走进来路的门」弹回去。第一版用"走出判定圈才解锁"，
  但 `checkDoors` 只在房间清空后才会被调用，boss 房清空瞬间玩家
  常因为最后一击的位置或击退，恰好停在来路门判定圈内——
  "走出过判定圈"这个前提从未发生，门被永久锁死。改成固定 80 帧
  豁免期后，六关（含所有支线房间）批量测试全部能正常通关。
- **奖励房必须判断"是否已经清空过"再决定要不要弹三选一**。第一版没判重，
  原路走回一间选过的奖励房会重新弹出选择——玩家靠来回横跳就能无限刷加成。
- **首领的出手频率不能和杂兵一样短**。第一版 `tokenCooldown` 给了全场最短
  的 26 帧（想法是"boss 该支配节奏"），实测 bot 在 11 秒内被打死，boss 自己
  的血量都没掉到能触发阶段二。伤害、判定范围、出手频率三个维度同时拉满，
  等于把 M1「同时能打你的人数决定能不能玩」的教训换个形式在单体身上重演。
  调到 50 帧（略高于杂兵的 42）后，才有反应窗口。

### 验收标准

1. 单关时长落在 **3-5 分钟**（统计 20 局中位数）
2. 首轮通关率 **30%-60%**（太高没挑战，太低劝退）
3. 三条成长路线的选取率都 **> 20%**（有路线没人选说明它是废的）
4. **教学序列生效**：玩家在第 2 关首次遇到盾兵后，该关的纵深移动占比
   应显著高于第 1 关。不涨说明新敌人没逼出新打法。（LEVEL_DESIGN 第十一节）

### 当前状态：机制实测与真机复核通过

和 M1 同样的纪律：机制跑得通不等于好玩。脚本 bot 验证过首领的阶段切换、
召唤、招式池、预警覆盖全部精确无误（多组独立测试 unwarnedLethal 恒为 0），
调整过一次明显失衡的数值（tokenCooldown 26→50）。但脚本 bot 的走位判断
比较简陋（分不清预警段和执行段），没能验证"首领在合理打法下能否被真人
稳定打赢"——这条必须交给真人游玩，验收标准第 2 条（首轮通关率）也是。

### 后续持续观测

职业实装后继续用六关回归记录每关实际用时、是否首轮通关、三选一选择；
职业不能以破坏已经通过的关卡节奏为代价制造差异。

## M4 · 装备系统 🚧 已开工

已完成三槽位、库存、职业限制、武器动作覆盖链、精英/首领清房轮换掉落、
装备面板，以及六把职业武器、三套护甲和三件饰品的差异化效果。装备与库存
跨关保留，但生命、能量和局内成长仍按关卡重置；完整经营存档留给 M5。

### 需要先决策：武器和职业谁说了算

两边都声称自己"决定招式组"，不先分层级会打架。**决策**：职业决定
"这个角色能做哪一类动作"（重击的蓄力单段 / 疾锋的多段连击 / 术法的
范围爆发），武器在职业划好的框架**内**提供数值和参数微调——同一职业
的三把武器不改变动作类型，只改伤害分布、判定框大小，或解锁一个职业
本来就有但没点亮的分支（比如疾锋的某把武器专属解锁 `slash4`）。职业
回答"我在打哪种游戏"，武器回答"这把打起来手感差多少"。技术上是
M2 `resolveAction` 查表链再叠一层：`WEAPON_ACTIONS[weapon]?.[action] ?? PROFESSION_ACTIONS[profession]?.[action] ?? ACTIONS[action]`。

**决策**：不做品质/稀有度分级。三槽位 + 词条随机的模型已经够表达
"变强"，再加一条品质轴只会让"值不值得换"变复杂，却不会让手感差异
更明显——手感差异应该来自"招式真的不一样"，不是"数值大了一圈"，
这条延续现有约束"不做复杂的装备词条组合"，不是新约束。

### 要做

- [x] 三槽位数据结构：武器 / 护甲 / 饰品，武器槽携带"职业限定"字段
      （术法武器不能装到重击身上），护甲/饰品职业无关
- [x] `WEAPON_ACTIONS` 覆盖表：按上面的查表链，允许武器对职业默认
      招式表做局部覆盖，不覆盖的字段退回职业默认值
- [x] 局内掉落：复用现有战斗结算/房间清空的事件钩子，不需要新的
      掉落系统框架
- [x] 装备界面：复用 `drawUpgradeChoice`/`drawStageSummary` 的
      "全屏遮罩 + 卡片"语言，装备槽用职业选择界面同一套卡片组件
- [x] 首批护甲/饰品效果：行阵甲降低承伤，收魂佩提高处决回复；效果与成长
      路线叠加且进入伤害/回复的统一结算出口
- [x] 每个职业至少两把差异化武器，并提供三套通用护甲和三件饰品；精英/
      首领掉落按关卡稳定轮换，每次提供武器、护甲、饰品各一个候选
- [x] 复用真人局样本记录配装，`__game.equipmentReport()` 输出头部配装占比
      和 `< 40%` 门槛结果；是否通过仍需真实样本判定
- [x] 三批 2×2 源网格覆盖全部 12 件静态装备图标，跑通 Codex 上游、确定性
      切图、64×64 联络表、游戏内回退与运行截图证据

### 验收标准

1. 换武器后**招式手感明显不同**，不是数值皮肤
2. 没有唯一最优配装：统计玩家配装分布，头部配装占比 **< 40%**

## M5 · 基地经营层 ✅ 机制完成，待真机量化

经营主链和五栋建筑的实际收益均已接通；下一步只做首轮成本、等待时间和循环
吸引力的真机量化，不再增加新的经营子系统。

### 资源类型：至少三种，对应现有约束的三个梯度

现有约束"离线只产基础资源，图纸和高级材料必须打出来"已经暗含至少
两种资源，明确成三种：

| 资源 | 产出来源 | 用途 |
| --- | --- | --- |
| 基础材料 | 资源田离线产出 + 局内少量掉落 | 日常建造、低级装备 |
| 图纸 | 只能局内打出（首领/精英掉落） | 解锁新的装备/建筑配方 |
| 稀有材料 | 只能局内打出（高难关卡/首领） | 高级装备强化 |

三种资源对应"不打也行"的三个层级：基础材料不打也能慢慢攒，图纸和
稀有材料必须打——这是把现有约束落到可实现的数据结构上，不是新发明。

### 首日引导路径

五栋建筑一次性摊开会让新玩家无所适从，按通关次数分批解锁：

1. 第一次通关任意一关 → 解锁**演武场**，建成后同时开放重击与术法
   （呼应 M2 的解锁依赖决策）
2. 第二次通关 → 解锁**锻造台**首个装备槽位
3. 其余建筑（丹房 / 资源田 / 藏经阁）按后续几次通关依次解锁，
   不在首日一次性给全

- [x] 三种资源的产出/消耗账本，及对应的档案字段；多资源交易原子提交，
      余额不足整笔回滚，余额结果防溢出，流水设上限并在跨关时深拷贝；
      旧档案即使只缺部分 M5 子字段也能迁移
- [x] 五种建筑的解锁顺序表（对应上面的引导路径）：演武场 / 锻造台 /
      丹房 / 资源田 / 藏经阁按第 1-5 次通关逐栋开放；计数绑定 Boss 房首次

- [x] 建造队列与时间成本骨架：锁定/重复建造检查、资源原子扣除、串行起止

- [x] 离线收益结算：唯一入口只接受基础材料产速，支持收益时长上限、零碎

## 美术需求与产出规范

美术方向：**低多边形卡通 3D**。玩家 `hero-v2.png` 和六类敌人的独立
`enemy-*-v2.png` 已完成，共 132 帧通过同缩放、同脚底线和无触边的机械验收；
建筑仍待制作。boss 阶段二复用同一动作表，由运行时切换亮橙红强调色。

美术可以由专业工具、AI 或人工产出，但进入游戏前必须通过下面的格式、注册线、
剪影可读性和运行画面验收，不能用“单张看起来不错”代替动作表质量：

### 角色动作表

| 项 | 规格 |
| --- | --- |
| 格式 | PNG，透明背景 |
| 排布 | 一行一个动作，严格等分 |
| 行序 | idle / move / slash / slash2 / dash / hit（与 `core/actions.ts` 对齐） |
| 每行帧数 | 4-8 |
| 单格 | 96×96 或 128×128 |
| 视角 | 3/4 侧视（约 62° 方位角），不是纯侧面也不是正面 |
| 朝向 | **整套动作必须一律面向屏幕右侧** |
| 关键约束 | **所有动作必须共用同一套缩放与基准线**，否则切动作时角色会跳 |

朝向之所以是硬约束而不是美术偏好：渲染层用 `ctx.scale(e.facing, 1)` 做镜像，
`facing = 1` 时**不镜像**直接画。源图若面向左，游戏里就会永远背对目标——
攻击判定朝一边、人物挥向另一边。这条对盾兵尤其致命：正面减伤和背后弱点
按 `facing` 判定，画面上的盾会正好落在实际是弱点的那一侧，把「绕后」
这个机制教反。机械验收脚本查不出朝向，**必须人工逐张确认**。

3/4 而不是纯侧面的理由：纯侧面身体只剩一条窄边没有体积感，
正面则四肢摆动被透视压缩掉、走路看不出来。

### 敌人

同上规格。**五种敌人的剪影必须能区分**——
在 96px 下靠轮廓就能认出是盾兵还是远程，不能靠颜色区分。

2026-08-25 已完成：grunt 16 帧、shield 16 帧、ranged 20 帧、charger 20 帧、
elite 16 帧。源网格、逐帧报告和复核命令见
`docs/experiments/enemy-actions-2026-08-25/README.md`；boss 不包含在这五类内。

### 建筑

静态图，每栋三态（未建成 / 建造中 / 建成）+ 图标。无动作帧需求。

### 现有管线

`ai-asset-pipeline` 的枢轴动画管线可以出符合上述规格的表
（Blender 建骨架 → K 关键帧 → 正交渲染 → 打包），
但**几何质量取决于建模**，管线本身不解决"好不好看"。
它适合出规格正确的占位件和最终的动作烘焙，不适合做美术设计。
