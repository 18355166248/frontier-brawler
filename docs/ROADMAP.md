# 路线图

按**风险从高到低**排，不按"容易先做"排。
每个里程碑都有可判定的验收标准——"感觉还行"不算通过。

原则：**前一个里程碑不过，不开下一个。** 尤其是 M1 和 M2，
它们是"这游戏到底好不好玩"的答案，不过就该改方向而不是继续堆功能。

## M1 · 战斗深度 —— 最高风险 🚧 机制完成，待真人验收

目标：验证"这个战斗值不值得玩下去"。**不过就停，别往下做。**

### 要做

- [x] 五种敌人：杂兵 / 盾兵 / 远程 / 冲锋 / 精英
- [x] 处决机制（敌人 <25% 血可处决，回血回能）
- [x] 能量与技能（1 个范围技能起步）
- [x] 冲刺无敌帧 + 冷却
- [x] 敌人预警帧（冲锋和精英的起手要看得见）
- [x] 局内统计埋点（否则下面四条验收标准无从判定）

### 验收标准

1. **打法多样性**：录三局的按键序列，普攻占比 **< 60%**。
   如果还是一路平 A，说明深度不够，机制没生效。
2. **纵深有用**：盾兵和远程必须逼出纵深走位。
   统计：单局纵深移动距离 / 横向移动距离 **> 0.25**。
3. **处决被使用**：单局处决次数 **≥ 3**。用不上说明触发条件或收益不对。
4. **不觉得不公平**：所有致死伤害都有可见预警。逐个 review，不能有"凭空掉血"。

### 当前状态：机制实测通过，手感未验收

**必须分清两件事**：机制跑不跑得通，和这个战斗好不好玩。
下面的数字来自脚本 bot（`__game` 挂钩驱动，五局），只能证明**机制不是摆设**——
连脚本都打不出多样性的话，真人更不可能。**它不构成验收通过。**

| 标准 | 要求 | 脚本五局 | 机制判定 |
| --- | --- | --- | --- |
| 1 普攻占比 | < 60% | 31% / 39% / 33% / 46% / 47% | 5/5 达标 |
| 2 纵深比 | > 0.25 | 0.78 ~ 1.68，均值 1.12 | 5/5 达标 |
| 3 处决次数 | ≥ 3 | 0 / 4 / 3 / 3 / 3 | 4/5 达标 |
| 4 无预警致死 | 0 | 全部 0（含站桩挨打致死一局，14 次受击全部预警） | 通过 |

**验收第 1、2、3 条要的是真人按键序列，必须由人打三局才算数。**
玩完直接在控制台读 `__game.stats()`，四条标准的数字都在里面。

调参过程中被实测推翻的两处设计（`[已验证]`）：

- **冲锋的突进距离必须大于它的起手距离**。第一版突进只有 62px，
  而它在 190px 外起手——蓄力、预警、突进整套演完，人还在两个身位外。
  这个敌人类型当时等于不存在。现在突进约 197px，且会冲过头。
- **冲刺必须能朝纵深方向**。冲刺原本写死沿朝向走，于是"用冲刺躲"
  永远是横向位移，而远程和冲锋的攻击本来就是水平直线，横着躲不开。
  改成按输入锁定方向后，纵深比从 0.218 直接跳到 0.98——
  第 2 条能不能过，卡的根本不是敌人设计，是冲刺少了一个维度。

### 判定

三条以上不达标 → 战斗深度不足，回头改机制，不是加内容。

## M2 · 职业差异 —— 次高风险

目标：验证职业是不是三种游戏，而不是三个数字。

### 要做

- [ ] 三职业：重击 / 疾锋 / 术法
- [ ] 每职业专属动作数据（招式帧数、判定框、位移曲线都不同）
- [ ] 职业选择界面

### 验收标准

1. **打法真的不同**：同一关用三个职业各打三局，
   三者的按键分布、平均交战距离、单局位移距离必须显著不同。
   数值接近 = 设计失败。
2. **不能有明显最优解**：三职业通关同一关的成功率差 **< 20%**。
3. **手感可辨识**：蒙住 UI 只看动作，能认出是哪个职业。

## M3 · 关卡与推进

- [ ] 波次系统（一关 4 波 + 关底首领）
- [ ] 局内三选一成长（锋芒 / 玄术 / 守元）
- [ ] 首领：分阶段，每阶段换招式组
- [ ] 结算界面

### 验收标准

1. 单局时长落在 **3-5 分钟**（统计 20 局中位数）
2. 首轮通关率 **30%-60%**（太高没挑战，太低劝退）
3. 三条成长路线的选取率都 **> 20%**（有路线没人选说明它是废的）

## 美术需求（不由 Claude 产出）

美术方向：**低多边形卡通 3D**。当前 `public/art/` 里是占位盒子人，需要替换。

Claude 不做美术设计。这里只写**规格**，产出交给专业工具或人：

### 角色动作表

| 项 | 规格 |
| --- | --- |
| 格式 | PNG，透明背景 |
| 排布 | 一行一个动作，严格等分 |
| 行序 | idle / move / slash / slash2 / dash / hit（与 `core/actions.ts` 对齐） |
| 每行帧数 | 4-8 |
| 单格 | 96×96 或 128×128 |
| 视角 | 3/4 侧视（约 62° 方位角），不是纯侧面也不是正面 |
| 关键约束 | **所有动作必须共用同一套缩放与基准线**，否则切动作时角色会跳 |

3/4 而不是纯侧面的理由：纯侧面身体只剩一条窄边没有体积感，
正面则四肢摆动被透视压缩掉、走路看不出来。

### 敌人

同上规格。**五种敌人的剪影必须能区分**——
在 96px 下靠轮廓就能认出是盾兵还是远程，不能靠颜色区分。

### 建筑

静态图，每栋三态（未建成 / 建造中 / 建成）+ 图标。无动作帧需求。

### 现有管线

`ai-asset-pipeline` 的枢轴动画管线可以出符合上述规格的表
（Blender 建骨架 → K 关键帧 → 正交渲染 → 打包），
但**几何质量取决于建模**，管线本身不解决"好不好看"。
它适合出规格正确的占位件和最终的动作烘焙，不适合做美术设计。
