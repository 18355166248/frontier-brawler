# Godot 底层重构评估

评估日期：2026-09-27。状态：第一阶段 Godot 首关已实施，尚未完成全量迁移。

## 实施记录

独立工程已落地在 `native/godot/`。已完成 42 项自动行为检查、真实渲染截图与
桌面 50 单位短时压力测试；旧版 `npm run build` 已通过。
范围、已知差异和验收证据见 [首关说明](../native/godot/README.md) 与
[验证记录](../native/godot/docs/validation.md)。下文保留初始评估依据；“本次评估”指
建立方案时的只读检查，实际实施状态以上述记录为准。

## 结论

适合尝试 Godot 4 + GDScript 的原生 2D 重构，保留横版带纵深的战斗形式。
收益主要来自可编辑的场景、独立角色组件、动画工具、UI 布局与统一生命周期。
引擎替换本身不保证改善画面、手感或帧率；必须用完整首关和同屏压力场景验证。

现有 Web 与 Cocos 项目作为迁移对照。建议新工程放在 `native/godot/`；完成验收后
再切换正式入口。现已在此路径建立首关工程，现有 Web/Cocos 入口不变。

## 当前结构与问题依据

| 位置 | 当前职责 | 重构重点 |
| --- | --- | --- |
| `src/render/renderer.ts`，1981 行 | 战场、角色、特效、HUD、职业选择、装备、基地、结算 | 拆成场景、角色表现组件和独立 UI 面板 |
| `src/core/world.ts`，1072 行 | 输入缓冲、动作推进、AI 调度、判定、伤害、弹体、推挤 | 分离角色状态、战斗结算和敌人调度 |
| `src/core/run.ts`，841 行 | 房间流程、职业、装备、基地、成长、统计 | 分离单局流程与长期进度服务 |
| `src/main.ts`，827 行 | 启动、输入、保存、暂停、循环、调试 | 由入口场景协调独立服务 |
| `native/cocos-poc/assets/scripts/FrontierPoc.ts`，787 行 | 输入、相机、资源、HUD、精灵、生命周期 | 已接入引擎，但仍集中在一个试验组件 |

行数只描述规模；判断来自同一模块承载多种职责，并非仅因文件长就要求拆分。

可保留的设计已有价值：`World` 不依赖渲染；`Run` 管房间、`World` 管单场战斗；
动作、装备、关卡有集中定义；战斗事件可用于音效与表现。这些边界应继续保留。

Cocos 当前实现集中在第一关。`syncEntitySprites()` 只覆盖英雄、杂兵和 Boss，
不能按 Web 版的六关完整度评估它。迁移文档也明确基地、存档、音频等尚未迁入。

英雄图集只有 idle/move/slash/slash2/dash/hit 六行。Web 缺失动作退回 idle 或
slash2，Cocos 则把多个动作复用到 slash2/move。换引擎不会生成缺少的动作姿态；
专属动画是独立的表现改造工作。

## 推荐边界

| 内容 | 处理方式 |
| --- | --- |
| 英雄、六类敌人、建筑和装备 PNG | 复用；重新配置图集、脚底锚点和过滤模式 |
| 职业、动作帧、装备、关卡、基地数值 | 保留初始设计，转换成 Godot Resource 或中间 JSON；包含计算规则的 TS 函数需重写 |
| 输入缓冲、连招取消、无敌、处决、Boss 阶段 | GDScript 重写，并用旧版固定输入场景核对 |
| Canvas 绘制、Cocos 组件、DOM 触控 | 替换成 Godot 场景、Control、InputMap 与触摸适配 |
| Web Audio 合成音效 | 事件语义保留，播放实现迁移；可离线生成采样后导入 |
| localStorage 存档 | 使用 `user://` 存储；旧档通过显式 JSON 导出/导入迁移，不能假设原生端能直接访问浏览器存储 |
| 当前自动化 | 作为规则参考；Godot 增加行为回归和实际场景验收，不照搬浏览器接口 |

不建议为了继续运行 TS 引入额外脚本运行时作为默认架构。
Godot 官方支持 GDScript、C# 和通过 GDExtension 使用的 C/C++；TS 并非官方脚本语言。
本项目以 GDScript 为首选，可减少额外绑定依赖。

## 建议职责划分

```text
Main                         启动、场景切换
├── CampaignState            长期进度、职业、装备、基地
├── SaveService              版本校验、持久化、旧档导入
├── RunController            单局、房间推进、奖励、结算
│   └── Room                 地面、边界、门、出生点
│       ├── Actor            地面坐标、生命、移动
│       │   ├── ActionState  逻辑帧、取消窗口、输入缓冲
│       │   ├── Combat       判定、受击、无敌、击退
│       │   └── Visual       图集、跳跃偏移、受击表现
│       ├── EnemyDirector    进攻名额、刷怪、Boss 阶段协调
│       └── CameraRig        跟随、边界、屏震
└── UI                       HUD、触控、暂停、奖励、基地、结算
```

这些是职责边界，不要求每个名词都建立一个全局单例。角色与房间使用可编辑、可复用
场景；数据定义使用 Resource；UI 通过事件响应流程，避免直接修改战斗内部状态。

战斗保留 60Hz 逻辑帧。动作逻辑是判定与动画进度的唯一时间来源，不能让
动画播放结束回调和战斗状态机分别决定动作结束。命中停顿冻结战斗推进，但 UI
和必要特效继续运行；后台暂停要清空输入，恢复不能补跑后台积累的逻辑帧。

角色地面位置与跳跃视觉高度分开。Y 排序依据脚底位置，不能因角色跳起改变前后
遮挡。移动碰撞可由 CharacterBody2D 等节点承接，但攻击仍需保留纵深、腾空、
同一招命中去重和生效帧规则；不能直接用持续重叠信号替代全部战斗判定。

## 实施顺序与验收

1. **工程与风险场景**：导入正式英雄、杂兵、Boss；打通移动、攻击、闪避、跳跃、
   相机和纵深排序。增加 50 单位压力入口，测真实渲染、碰撞与 AI，不只测空节点。
2. **完整首关**：首页/开局 → 战斗 → 奖励 → 教学 Boss → 战利品 → 结算 → 重开，
   同时支持暂停、后台返回与键盘/触控。首关职业可从已解锁的疾锋开始。
3. **全量规则迁移**：三职业、六类敌人、六关、装备、基地、周目与存档。
4. **表现与发布收口**：补缺失动作、改善场景和音效，再完成目标平台导出及真机验证。

首关通过门槛：

- 真实操作可以通关和战败，结算只发生一次，连续重开三局无残留角色、输入或监听。
- 固定输入用例覆盖连段取消、输入缓冲、闪避无敌、跳跃避地面攻击、处决门槛与
  Boss 阶段；以旧版规则作为初始对照，允许调整的差异需单独记录。
- 所有实际用到的动作映射可追踪，复用帧明确标记；动画与命中窗口同步。
- 50 单位时记录平均/P95 帧耗时和内存；目标设备接近稳定 60fps 是验收目标，
  目前没有 Godot 运行数据，不能宣称已达到。
- 移动端验证摇杆与动作多指并用、触摸取消、安全区、切后台与音频恢复。

平台尚待确定。现有文档写 Android/HarmonyOS 原生竖屏；本次评估不把旧目标视为
新的确认。建议先桌面验证再做 Android 真机；如仍需 HarmonyOS，应明确是否要求
原生鸿蒙，并单独验证导出链路，不能以 Android APK 构建成功代表支持。
如果 Web 是首发渠道，则需优先验证下载体积、首屏和移动浏览器表现。

## 初始评估阶段的验证与边界

- 本机 `godot --version`：`4.7.2.stable.official.ed1daf0bf`，可进行本地工程验证；
  未验证相应平台导出模板。
- `npm run check`：通过。
- `npm run validate:native-stage`：通过，验证共享 TS 首关状态路径；脚本主动清怪，
  不是实际战斗通关或 Cocos 真机证明。
- `npm run validate:fixed-step`：通过，覆盖 60Hz、补帧上限、暂停与异常时间。
- 本次未修改运行时代码，也没有完成 Godot 原型、视觉验收或性能对比。
