# Frontier Brawler

横版割草闯关 + 基地经营。当前有**六关可玩**：DNF 式房间推进 + 小地图，
每关引入一种新敌人，终点都是分阶段首领。战斗深度（M1）与关卡系统（M3）
的机制都已实现，但**都还没有真人验收**——脚本能证明机制不是摆设，
证明不了好不好玩。还没有经营层。

关卡设计见 [docs/LEVEL_DESIGN.md](docs/LEVEL_DESIGN.md)。

技术栈 Vite + TypeScript + Canvas 2D，没有引擎。

## 为什么不用 Cocos

逻辑层本来就该是引擎无关的 TS —— 这是从 `xianxia-roguelike` 学到的：
它的 32 个战斗系统文件**零 Cocos 依赖**，5300 行逻辑随时能搬，
而耦合全压在一个 9800 行的编排层里。

所以这里从第一行就把线画清楚：

```text
src/core/     纯逻辑，不引用任何渲染 API。换引擎时一行不动。
src/render/   Canvas 渲染层。换 Cocos 只重写这里。
```

原型阶段用 Canvas 是因为迭代和验证都快得多；
将来要发微信小游戏，再补一层 Cocos 渲染层即可，`core/` 直接复用。

## 手感设计

**固定 60Hz 逻辑步长**，渲染跟显示帧率。所有手感数值（前摇、硬直、击退衰减）
以逻辑帧为单位，144Hz 屏和 60Hz 屏打起来一致。

**帧数分配就是打击感**（见 `core/actions.ts`）：
第一段挥砍前摇 8 帧，第 9-11 帧判定生效，之后收招。
挥出只占 3 帧所以显得快，命中定格再冻结整个世界 5 帧让力道落地。

**攻击令牌**（见 `core/world.ts` 的 `enemyThink`）——这条是实测逼出来的。
最初五个敌人同时贴脸输出，玩家每次受击进 20 帧硬直，永远轮不到自己出手，
实测就是站着被打死。而且不是数值问题：把敌人伤害调到 1 也一样操作不了。

令牌把「同时能打你的人数」压到 2 个，其余的在待机圈上游走。
玩家因此始终有出手窗口，围殴的压迫感却还在。交还令牌时给 42 帧冷却，
否则同一个敌人会立刻抢回去，轮流进攻退化成一个人贴脸连打。

**纵深移速压到横向的 62%**：不压的话斜着走比横着走快，而且纵深过快会破坏横版的空间感。

**冲刺方向由输入锁定**——这条是被数据逼出来的。冲刺原本写死沿朝向走，
于是"用冲刺躲"永远是横向位移，可远程和冲锋的攻击本来就是水平直线，横着躲不开。
改成起手时按方向键锁定方向后，纵深移动占比从 0.218 跳到 0.98。
**纵深有没有用，卡的不是敌人设计，是冲刺少了一个维度。**

**预警是数据驱动的**：每个招式在 `core/actions.ts` 里声明自己的预警形状和帧数，
渲染层照着画，统计层同时记下"这一下有没有预告过"。
所以"所有致死伤害都有预警"不是靠人工 review，而是一个能直接读的数字。

**取消窗口必须显式声明**——这条是从一个真实 bug 里学到的。冲刺定义了
`cancelInto: ['slash']`（冲刺接普攻），但 `canInterrupt` 对没有判定框的
动作默认"播到最后一帧才能取消"，26 帧冲刺只有第 25 帧能接，窗口窄到
玩家按不出来，等于白写。加一个显式的 `cancelFrom` 字段覆盖这条隐式规则，
「功能写在代码里」和「玩家能感知到的操作窗口」才是同一件事。
跳跃接跳劈也是靠同一个字段撑起来的。

**跳跃只免疫贴地判定，不是全无敌**：`Hitbox.hitsAir` 默认 false，
大多数攻击（挥砍、突进、重击、弹丸）打不到腾空目标；但首领阶段二的
范围技 `bossNova` 标了 `hitsAir: true`，跳了也没用。这条边界不是随便画的——
如果跳跃能躲开一切，冲刺的无敌帧就没有存在的意义了。两种防御手段
必须"躲的东西不一样"，才有"这下该冲还是该跳"的判断。

**"方向键+动作没效果"要拆开看，不能一刀切改**——这条是真实反馈逼出来的。
跳跃第一版起跳只有约 4px 的固定前冲，且不响应方向锁定，玩家反馈"跳跃+
方向键没用"；攻击也有同样的反馈。但两者的根因和该改的地方完全不同：
跳跃需要真正的方向锁定 + 明显位移（改成约 34px 的弧线，冲刺约 46px，
同一量级但略小），攻击只需要起手转身、位移完全不用变（要的是"能打
另一侧的敌人"，不是"打一下还带位移"）。连段中途不响应方向——不然
第二段打到一半角色转向会显得很怪。

**取消链要覆盖"落地"这个状态转换，不能只在半空里打转**：跳跃刚做出来时
只支持「跳跃 → 跳劈」，跳劈播完就回 idle，是一条孤立的空中招式，和地面
连段是断开的。补上「跳劈落地 → 接一次挥砍」之后，「跳跃躲判定 → 跳劈
追打 → 落地接连段」才是一条完整的空对地连招，不是打完就没了。
落地这个取消点必须精确等于 `airborne.to`（这里是 16 帧），不能用判定框
收尾的默认规则（第 11 帧）——那样会在人还悬空时就切成地面 slash，
出现"半空中挥地面刀"的违和，这正是重构 `startAttack` 时特意规避的问题。

**位移语义不兼容的动作之间要挡住取消，不是都放行**：腾空（跳跃/跳劈）
时按冲刺键技术上能触发切换，但冲刺是纯地面位移，没有腾空语义，切换
瞬间人会"凭空消失、贴地冲出去"，跟落地那一下完全脱节。反过来「冲刺
接跳跃」是自然的（贴地滑行后一跃而起），所以只挡"腾空接冲刺"这一个
方向，不是笼统地禁止所有交叉取消。

**完美取消：取消窗口打通之后，"接得准不准"还得有反馈**——普通取消窗口
有十几帧宽容度，只要能接上，早一帧晚一帧手感上没区别，连段深度停在
"知道能接"，到不了"接得多准"。在每个可取消窗口最早的 3-4 帧里再单独
标一段"完美窗口"（`core/actions.ts` 的 `perfectCancelWindow`），在这段
里触发的取消，下一下命中伤害 ×1.15。只覆盖有伤害判定的进攻性转换
（普攻两段、冲刺/跳跃/跳劈接攻击），处决和技能不走这条判定分支，
不参与加成。

**真人反馈"打斗不够丝滑、动作不连贯"，落地成两处具体修复，不是玄学调参**：

- **输入缓冲**：攻击/冲刺/跳跃/技能/处决之前都是"按下那一瞬间"边缘触发，
  提前几帧按连段下一击、落在还不可打断的窗口里就直接被丢弃，玩家得掐着
  帧数精确落在收招段才按得出来。现在各加 8 帧（约 133ms）缓冲：按下先记
  一份，动作转入可打断状态那一刻自动补发，缓冲期内没等到就作废。
- **收招段其实完全走不动**：普攻两段/冲刺/跳劈的位移曲线是"前几帧冲一下，
  后面一长串收招帧全是 0"，但原判断是"数组还有值（不管是不是 0）就由曲线
  接管"，导致收招段虽然 `interruptible` 已经打开、能接下一击，自由走位分支
  却始终轮不到，人像焊在地上。现在改成只在这一帧数值非 0 时才由曲线接管，
  降到 0（也是收招段开始的地方）立即放行给自由走位。跳跃不受影响——它的
  弧线中途没有回到 0 的帧，本该一次性播完，不该被走位打断。

**继续排查同一条反馈线，又抠出两处"输入黑洞"**：

- **普攻二段收招时按攻击键完全没反应**：`slash2` 没有 `cancelInto`（它是
  两段连招的终点），本该退回"重新起一次挥砍"的兜底分支，第一版却把
  `slash2` 也排除在这条兜底之外——两段打完，收招段再按攻击键精确地什么
  都不发生，必须等它自然播完回 idle 才能再出手。玩家的操作节奏是对的，
  游戏没接住。去掉这条多余的排除后，收招段接攻击键会循环回第一段，
  两段连招才是循环而不是"打完就断"。
- **受击硬直实际锁的时间比文档写的长了近三分之二**：`hit` 播 20 帧，
  真正的硬直时长是单独维护的 `stunFrames`（12 帧，和数值框架一致），
  但 `hit` 没写 `cancelFrom`，落进"播到最后一帧才能打断"的隐式规则
  （frame 19）——`stunFrames` 在 frame 12 就清零了，玩家却要等到 frame 19
  才能重新出手，多出 7 帧没人设计过的隐形硬直。补上 `cancelFrom: 12`
  后两者对齐。这条对两边都生效：被打的敌人也少卡 8 帧，不只是玩家受益。

**技能/处决原来能在半空中触发，人会瞬间"贴地"**：两者都没有 `airborne`
字段也没有位移曲线，渲染层的跳跃高度偏移只认 `jump`/`airSlash`——腾空时
按技能或处决键，角色会从跳跃弧线的任意高度瞬间切成地面姿态，是一次没有
过渡的跳变。这和冲刺当年在腾空时触发的问题一样，冲刺已经挡住了，这两个
漏掉了。现在给它们也加上 `!isActionAirborne(...)` 检查：腾空时按下会被
输入缓冲记住，落地那一刻自动补发；一直不落地就超出缓冲窗口，请求作废。

**连段的视觉表现补了三个纯程序化特效，不等美术帧**：玩家动作表只有
idle/move/slash/hit 四行，`slash2`/`dash`/`jump`/`airSlash`/`skill`/
`execute` 没有专属帧，取帧时全部退回 idle——两段连招打出去，第二下在
画面上其实就是"角色维持 idle 摆动"，看不出是又挥了一刀。补齐动作表是
真正的美术工作，不在自动化范围内，但"这一下打没打出去能不能在画面上
读出来"可以先靠程序化特效撑住：

- **挥砍弧光**：`slash`/`slash2`/`airSlash` 判定生效那几帧画一道扫过的
  弧光，角度颜色三招各不相同，纯读当前 `action`/`actionFrame` 和判定框
  算出来，不需要新状态。只画玩家——杂兵/盾兵的普攻也叫 `slash`，不分
  队伍的话敌人攻击会跟玩家自己的弧光撞色，分不清是谁打的。
- **冲刺残影**：冲刺无敌帧内画渐隐重影，残影消失的瞬间正好是收招段
  开放、能接攻击的时刻，把"冲刺"和"冲刺接攻击"连成一条线。
- **落地冲击环**：跳跃/跳劈落地那一帧（腾空状态从 true 变 false）在
  脚下画一圈扩散淡出的环，补上"跳跃躲判定→跳劈追打→落地接连段"这条
  连招里唯一没有反馈的瞬间。

三个特效全部是纯渲染层读状态计算，`core/` 不用改一行——因为它们要表现
的信息（判定窗口、腾空转换、无敌区间）本来就是 `core/actions.ts` 已经
声明过的数据，只是之前没有画出来。

**走动也补了两个程序化效果**：玩家和五类正式敌人都有走路帧，但只播腿部
姿态仍缺少落脚重量。现在 `move`
状态下身体按 `|sin|` 曲线一圈起伏两次（对应两步各踩一次，玩家 2px、
敌人 3px），配合脚落地帧补一个比落地冲击环小得多的灰尘点。灰尘的触发
判断用"帧号变化到落地点"而不是"当前帧号等于落地点"——后者在显示刷新率
高于逻辑帧率时会同一步触发好几次。

**结算界面的数据得跨房间累加，不能只读最后一间房**——`Run` 每进一间新房都会
建一个全新的 `World`，`World` 自己的 `RunStats` 只反映当前房间，切房间时
旧的那份连同旧 `World` 一起被丢弃。第一版差点直接拿 `world.stats.summary()`
喂给结算界面，六关里除了单房间首领关，其余关卡结算出来的击杀数、完美取消
次数全部对不上——因为前面几间普通战斗房的数据在切房间那一刻就已经跟着
旧 `World` 一起被垃圾回收了。现在 `Run.enterRoom()` 切房间前先把即将丢弃
的 `world.stats` 折进 `Run` 自己持有的 `stats` 里（`RunStats.absorb()`），
结算界面读的是 `Run.overallSummary()`：`Run.stats`（之前几间房的存量）+
当前 `world.stats`（还在进行中的这一间房，包括停在结算画面上的那间房，
因为它没有再触发一次 `enterRoom`）现算的合并结果，不提前修改 `Run.stats`
本身，避免每帧调用都重复叠加。

**首领招式衔接：范围技没能逼退玩家，就该有后续代价**——阶段二原本每次
选招都是纯距离 + 固定节奏的无记忆判断，`bossNova` 打完后接什么招跟
"刚放过范围技"这件事完全无关，玩家躲过一次范围技的长前摇之后就再没有
跟进压力。现在 `bossNova` 收招时如果玩家还在重击范围内，下一招强制接
`bossSlam`，攻击令牌横跨两招直到 `bossSlam` 自然播完才释放——这才是一次
决策窗口打出两下的连续技，而不是两次凑巧挨着的独立判定。玩家仍能在
`bossNova` 的长前摇里拉开距离换成被 `bossCharge` 追这条更有回旋余地的
分支，不是纯粹的死局。

## 美术

`docs/ROADMAP.md` 末尾列了角色动作表、敌人、建筑的**规格要求**。本轮角色
美术由内置 imagegen 生成身份参考和动作源网格，再由仓库内确定性工具完成
抠图、统一缩放、脚底注册与验收；建筑仍待后续制作。

玩家当前使用 `public/art/hero-v2.png`：低多边形卡通 3D，按
`idle / move / slash / slash2 / dash / hit` 六行、每行四帧排布。它由同一角色
参考生成 2×2 纯洋红动作网格，再经确定性切格、chroma 抠图、统一缩放、脚底
注册和 alpha 清理得到；24 格共用同一个缩放倍率和 `y=90` 脚底线，且没有格子
触边。完整实验和提示词见 `docs/experiments/ai-sprite-consistency-2026-08-25/`。

六类敌人当前分别使用 `enemy-grunt-v2` / `enemy-shield-v2` /
`enemy-ranged-v2` / `enemy-charger-v2` / `enemy-elite-v2` / `enemy-boss-v2`，
共 27 行、108 帧。
每类独立注册，动作行与各自状态机对齐；全部共用 96×96 单格和 `y=90`
脚底线。源网格、行序和复核方式见
`docs/experiments/enemy-actions-2026-08-25/README.md`。boss 五个专属动作已接入，
阶段二在同一动作表上切换为亮橙红强调，避免换表造成动作相位跳变。

后续需要骨骼级强一致性或制作首领时，仍可复用
[`ai-asset-pipeline`](../ai-asset-pipeline) 的 Blender 管线：搭骨架 → K 关键帧 →
正交相机渲成透明序列帧 → 打包成一行一动作的表。

```bash
cd ../ai-asset-pipeline
python src/render_clip_set.py --out output/frames/fb --prefix hero --view side --size 192 \
    --clips idle:4:loop move:4:loop slash:4 hit:4
python src/pack_action_sheet.py --rows \
    idle=output/frames/fb/hero_idle move=output/frames/fb/hero_move \
    slash=output/frames/fb/hero_slash hit=output/frames/fb/hero_hit \
    -o ../frontier-brawler/public/art/hero.png --cols 4 --cell 96
```

旧 `enemy.png` 不再参与渲染，仅作为历史占位文件保留。

## 开发期调试挂钩

开发模式下 `window.__game` 暴露了几个方法，用来绕过键盘焦点做自动化验证：

```js
__game.restart()                  // 重开
__game.hold({moveX: 1})           // 持续注入输入，{} 清空
__game.tap({attack: true})        // 按一下
__game.pause() / __game.resume()  // 定格检查某一帧
__game.world                      // 读世界状态
__game.fastForward(600)           // 脱离渲染循环快推 600 帧
__game.stats()                    // 本房间统计，M1 四条验收标准都在里面
__game.overallStats()             // 整关(跨房间)累计统计，结算界面画的就是这份数据
__game.profession('swift')        // 开发期切换职业：heavy / swift / arcane
__game.equip('wind-sabers')       // M4 装备实验武器；职业不匹配会返回 false
__game.equip(null, 'weapon')      // 卸下武器，回到职业默认动作
__game.grantEquipment('wind-sabers') // M4 调试：先把装备收入库存，再调用 equip
__game.professionReport()         // M2 已记录样本的三职业聚合对比
__game.professionSamples()        // M2 原始样本；每次通关或死亡自动记录
__game.clearProfessionSamples()   // 清空本机 M2 验收样本
__game.unwarned()                 // 无预警伤害明细，验收第 4 条逐条 review 用
__game.run                        // Run 状态：当前房间、已清空集合、门状态
__game.progress()                 // 关卡进度摘要
__game.stage(3)                   // 跳到第 3 关
__game.goto('c2n')                // 跳到本关某个房间 id（见 core/stages.ts）
__game.clearRoom()                // 清空当前房间敌人，验证开门与切换用
```

Canvas 视觉回归也可用开发地址直达教学房，例如
`http://127.0.0.1:4317/?stage=3&room=c1&profession=swift`；`stage` 从 1 起，`room` 必须属于该关，
`profession` 可选 `heavy`、`swift`、`arcane`。
这条入口只在开发模式存在，生产构建会移除。

注入输入有个坑：攻击/冲刺/技能/处决都取"按下那一瞬间"，
连续两帧都按住只会触发一次。脚本里要模拟连按，中间得插一帧松开：

```js
const press = (i) => { __game.hold(i); __game.fastForward(1); __game.hold({}); __game.fastForward(1); };
```

生产构建里这段会被 tree-shake 掉。

__game.overallStats()

第 1、2、3 条要的就是真人的按键序列。

## 已知问题

- `R` 重来在浏览器里按键有时不生效，用 `__game.restart()` 可靠。焦点处理待修。
- boss 已有 `bossSlam/bossCharge/bossRush/bossNova/bossSummon` 五行正式美术；
  几何轮廓只在动作表加载失败时作为容错兜底。

  新增的 skill/execute/jump/airSlash 等动作没有对应美术帧，会退回 idle；
  疾锋 `slash3`、重击释放和术法 `arcanePulse` 在专属美术补齐前复用
  slash2 行，重击蓄力复用 idle。跳跃的高度变化靠渲染层
  的 Y 轴偏移体现，不依赖专属美术帧，
  所以视觉上能看出「在跳」，只是角色本身的姿态还是 idle 那张。
- 三职业专属动作美术、装备和经营层尚未实现。
- 没有音效。
